## 1 概述

板端每秒检查一次视觉和哭声检测的当前结果，把"遮脸/翻身、离开画面、越出安全区域、哭闹"整理成一段一段的**事件**（何时开始、持续多久），保存在 `runtime/care/events.json`。这些事件有两个用途：

1. **App 查询**：`/api/events` 返回事件列表，`/api/events/summary` 返回最近一段时间的统计和摄像头当前状态。App 在「AI 问答」页显示"设备观察"卡片。
2. **大模型上下文**：家长提问时，`build_context()` 把最近 2 小时的事件统计和当前画面状态写进系统提示词，并在回答卡片上显示一个"画面：… · 近 2 小时哭闹 N 次"标签。

```text
VisionWorker（YOLOv8-pose）──┐
                             ├─ AppRuntime._watch_events（每 1 s）→ EventLog.observe()
YAMNet 哭声状态机 ───────────┘                                     │
                                                                   ├─ runtime/care/events.json
                                                                   ├─ GET /api/events、/api/events/summary → App「AI 问答」页
                                                                   └─ ChatAssistant → build_context() → 系统提示词 + facts
```

现有的 `/api/alerts`（实时告警）不变，App 的告警通知逻辑也不变。事件日志记录的是"发生过什么"，告警接口给出的是"现在正在发生什么"。

## 2 通用约定

- **地址**：`http://<板子IP>:7860`（局域网，无需鉴权）。
- **响应格式**：成功为 `{"ok": true, "result": ...}`；参数错误返回 HTTP 400 和 `{"ok": false, "error": "<原因>"}`。
- **时间**：返回值中的时间都是 Unix 时间戳，单位为**秒**（浮点数）。查询参数 `since`、`until` 可以传秒或毫秒，大于 10¹¹ 的数按毫秒处理（App 传毫秒）。
- **缓存**：响应带 `Cache-Control: no-store`，与其他接口一致。

## 3 事件模型

### 3.1 事件类型

| `type` | 含义 | `source` | 判定依据 | 开始条件 | 结束条件 |
| --- | --- | --- | --- | --- | --- |
| `cry` | 哭闹 | `yamnet` | YAMNet 双阈值状态机的 `crying` | 一出现即开始（状态机已平滑） | 连续 3 s 不哭 |
| `face_cover_rollover` | 遮脸/翻身 | `vision` | 鼻子和双眼关键点置信度都低于 0.25 | 连续 2 s 成立 | 连续 5 s 不成立 |
| `boundary` | 越出安全区域 | `vision` | 有可信身体关键点在 App 框选区域外 | 连续 2 s 成立 | 连续 5 s 不成立 |
| `no_person` | 离开画面 | `vision` | 没有检测到人 | 连续 5 s 成立 | 连续 5 s 不成立 |

补充规则：

- **开始时间**取条件第一次成立的时刻，不是满足"连续 N 秒"的时刻；**结束时间**取最后一次成立的时刻。
- **合并**：同类事件结束后 30 s 内再次出现，视为同一次事件继续（`merged` 加 1），避免宝宝来回翻动被记成很多次。
- **未知输入**：摄像头没开、姿态结果超过 5 s 没更新、大模型回答期间 YOLO 暂停、YAMNet 未就绪时，对应类型记为"未知"，不会开始或结束任何事件。未知状态持续 120 s 后，进行中的事件在最后一次成立的时刻结束，并标记 `interrupted: true`。
- **重启**：服务重启时，文件中仍"进行中"的事件在 `last_seen_at` 结束，并标记 `interrupted: true`。

### 3.2 事件字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | `<type>-<开始时间毫秒>` |
| `type` | string | 见 3.1 |
| `source` | string | `vision` 或 `yamnet` |
| `start_at` | number | 开始时间（秒） |
| `end_at` | number \| null | 结束时间（秒）；进行中为 `null` |
| `duration_s` | number | 持续秒数；进行中时为截至查询时刻的时长 |
| `ongoing` | bool | 是否仍在进行 |
| `last_seen_at` | number | 最后一次确认成立的时间（秒） |
| `peak_score` | number | 仅 `cry`：本次哭闹的最高哭声分数 |
| `merged` | int | 可选：合并进来的次数 |
| `interrupted` | bool | 可选：因输入长时间未知或服务重启而结束 |

### 3.3 摄像头当前状态 `vision_state`

| 取值 | 含义 | App 显示 |
| --- | --- | --- |
| `visible` | 检测到宝宝，面部可见 | 面部可见 |
| `covered` | 检测到人，但鼻子和眼睛都看不到 | 疑似遮脸/翻身（红色） |
| `no_person` | 没有检测到人 | 画面无人 |
| `paused` | 大模型回答中，YOLO 暂停 | 暂无实时结果 |
| `stale` | 姿态结果超过 5 s 未更新 | 暂无实时结果 |
| `unknown` | 摄像头未开启、尚无结果，或事件日志超过 10 s 没有采样 | 暂无实时结果 |

## 4 GET /api/events

按开始时间**从新到旧**返回事件。进行中的事件视为持续到当前时刻。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `since` | 否 | 只返回在此时间之后仍在进行或结束的事件（秒或毫秒） |
| `until` | 否 | 只返回在此时间之前开始的事件（秒或毫秒） |
| `type` | 否 | `cry` / `face_cover_rollover` / `boundary` / `no_person` |
| `limit` | 否 | 默认 100，最大 1000 |

## 5 GET /api/events/summary

返回最近 `window_s` 秒内每类事件的次数、累计时长和最近一次事件，以及摄像头当前状态。大模型上下文用的就是这个结果（窗口 7200 s）。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `window_s` | 否 | 统计窗口（秒），默认 7200，范围 60–604800 |

| 返回字段 | 说明 |
| --- | --- |
| `now` / `since` / `window_s` | 统计时刻、窗口起点（秒）、窗口长度 |
| `current.vision_state` | 摄像头当前状态，见 3.3 |
| `current.vision_state_at` | 该状态的采样时间（秒） |
| `current.active` | 当前正在进行的事件类型 |
| `types.<type>.count` | 窗口内的事件次数（与窗口有重叠即计入） |
| `types.<type>.total_s` | 窗口内的累计时长（秒，按窗口截断） |
| `types.<type>.latest` | 窗口内最近一次事件（字段同 3.2），没有则为 `null` |

示例（`GET /api/events/summary?window_s=7200`，程序实际输出，节选）：

```json
{
  "ok": true,
  "result": {
    "now": 1794078502.0,
    "since": 1794071302.0,
    "window_s": 7200.0,
    "current": {
      "vision_state": "covered",
      "vision_state_at": 1794078501.0,
      "active": ["face_cover_rollover"]

    "types": {
      "cry": {

        "latest": {"id": "cry-1794076950000", "type": "cry", "source": "yamnet", "start_at": 1794076950.0,
                   "end_at": 1794076989.0, "duration_s": 39.0, "ongoing": false, "last_seen_at": 1794076989.0, "peak_score": 0.82}
      },
      "face_cover_rollover": {
        "count": 1,
        "total_s": 12.0,
        "latest": {"id": "face_cover_rollover-1794078490000", "type": "face_cover_rollover", "source": "vision",
                   "start_at": 1794078490.0, "end_at": null, "duration_s": 12.0, "ongoing": true, "last_seen_at": 1794078501.0}

```

错误示例：`GET /api/events/summary?window_s=5` → HTTP 400，`{"ok": false, "error": "window_s must be between 60 and 604800"}`。

## 6 AI 问答接口的变化（POST /api/assistant/chat）

请求格式不变。每次提问时，`ChatAssistant` 调用 `EventLog.summary(window_s=event_window_s)`，`build_context()` 在"现在时间 / 睡眠状态"之后、室温湿度之前加入两行：

```text
摄像头当前画面：疑似遮脸或趴睡（鼻子和眼睛关键点都看不到），回答时先提醒家长立即查看宝宝。
最近 2 小时摄像头和麦克风的自动监测（可能有误报）：哭闹 2 次（最近一次 02:42 开始，持续 39 秒）；遮脸/翻身 1 次（最近一次 03:08 开始，仍在持续）。
```

- 第一行按 `vision_state` 选择：`visible` →"检测到宝宝，面部可见"；`covered` → 上面这句，并要求模型先提醒家长查看；`no_person` →"没有检测到宝宝"；其余状态不写这一行。
- 第二行列出窗口内次数不为 0 的类型（顺序：哭闹、遮脸/翻身、越出安全区域、离开画面）和最近一次的时间、时长；都为 0 时写"没有哭闹、遮脸/翻身、越界或离开画面的记录"。
- 两行都注明"自动监测（可能有误报）"，避免模型把检测结果当作确定事实。

NDJSON `start` 事件的 `facts` 多出一项（程序实际输出）：

```json
{"type": "start", "facts": ["今日喂养 0 次 · 睡眠 0 分钟", "画面：疑似遮脸/翻身 · 近 2 小时哭闹 2 次 · 遮脸/翻身 1 次"]}
```

格式：`画面：<当前状态> · 近 <窗口>哭闹 N 次 · 遮脸/翻身 N 次[ · 越界 N 次]`。当前状态未知时省略"画面："部分；越界为 0 时省略。

| 配置项（`config.json` 的 `assistant` 段） | 默认值 | 说明 |
| --- | --- | --- |
| `event_window_s` | 7200 | 写入上下文的事件统计窗口（秒） |

兼容与容错：

- 事件摘要在暂停 YOLO **之前**读取，所以大模型回答期间的 `paused` 状态不会进入本次上下文。
- 读取事件日志出错时按"没有事件信息"处理，回答照常进行。
- 不传事件信息时（`build_context(overview, room)`），上下文与以前完全相同。

## 7 App 端

| 位置 | 改动 |
| --- | --- |
| `EventModels.kt`（新增） | `BoardEventType`、`VisionState`、`BoardEvent`、`BoardEventSummary` 数据类与 JSON 解析 |
| `BoardApi.kt` | `eventSummary(windowSeconds = 7200)` → `/api/events/summary`；`events(sinceMillis, type, limit = 20)` → `/api/events`；失败或旧板端没有接口时返回 `null` |
| `AssistantPage.kt` | ① 打开页面或点刷新时读取事件摘要和最近 3 条事件；② 空白页显示"设备观察 · 近 2 小时"卡片：当前画面、四类事件次数、最近事件，并说明"提问时本地模型会参考这些观察"；③ 回答卡片上的视觉标签加摄像头图标，用第三色显示，"疑似遮脸"时用错误色；④ 新增示例问题"宝宝刚才睡得怎么样？"；⑤ 介绍文字加入"摄像头和哭声检测的观察" |

旧版板端没有这两个接口时，`eventSummary()` 返回 `null`，卡片不显示，其他功能不受影响。

## 8 存储与运行

| 项目 | 说明 |
| --- | --- |
| 文件 | `runtime/care/events.json`（原子写入：先写临时文件再改名） |
| 保留 | 7 天，最多 5000 条 |
| 写入时机 | 事件开始或结束时；有进行中事件时每 30 s 刷新一次 `last_seen_at` |
| 采样线程 | 主服务内的 `event-log` 线程，每 1 s 一次；异常只打印日志，不影响主服务 |
| 开销 | 每次采样只读取最近一次姿态结果和 YAMNet 结果，不做额外推理 |

## 10 已知限制

- 遮脸/翻身仍是单帧关键点规则，事件日志只加了 2 s 去抖，不能完全消除误报，所以上下文中注明"可能有误报"。
- 大模型回答期间（最长约 1 分钟）YOLO 暂停，这段时间不会产生新的视觉事件；哭声检测不受影响。
- 以 `--disable-yamnet` 启动时没有哭声事件；不开摄像头时没有视觉事件，`vision_state` 为 `unknown`。
- 事件类型目前只有 4 种，没有体动、睡眠时长等更细的视觉睡眠分析。
